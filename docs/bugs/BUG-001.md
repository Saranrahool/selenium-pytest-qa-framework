# BUG-001: Device search is case-sensitive

| Field | Value |
|-------|-------|
| Severity | Medium |
| Priority | Medium |
| Status | Open |
| Requirement | REQ-03 |
| Found by | TC-012, `tests/test_device_list.py::test_search_is_case_insensitive` |
| Environment | Chrome (headless), Fleet Device Portal `app/` |

## Summary
Searching the device list only matches when the text has the same capitalization as the data. "bus 214" returns no devices, but "Bus 214" returns two.

## Steps to reproduce
1. Sign in as `tester` / `Passw0rd!`.
2. On the device list, type `bus 214` in Search.

## Expected
CAM-1101 and NVR-2101 are listed (REQ-03: search is case-insensitive).

## Actual
No devices are listed and the count shows "0 device(s)".

## Root cause
`listDevices()` in `app/app.js` uses `indexOf()` on the raw strings without normalizing case.

## Suggested fix
Compare lowercase values:
```js
var q = searchText.toLowerCase();
var searchOk = !searchText || d.bus.toLowerCase().indexOf(q) !== -1 || d.id.toLowerCase().indexOf(q) !== -1;
```

## Workaround
Type the bus name or device ID with matching capitalization.
